## AI Agent, Risk Analysis, Disaster Simulations, External Data Integrations & Alerts

## 1. Executive Summary

Phase 4 of AgentCraft / RakshaGrid establishes the **Disaster Intelligence & Decision Support Layer**. It transforms the tactical incident and resource management foundation (Phases 1–3) into an active, analytical, and predictive emergency response platform.

Key Capabilities:
1. **External Disaster Data Integration**: Connects to authoritative, free global meteorological and hydrological APIs (Open-Meteo) with automatic in-memory caching and observation freshness tracking.
2. **Explainable Risk Assessment Engine**: Computes normalized 0–100 risk scores with transparent contributing factor breakdowns, data gap penalties, and deterministic categorization:
   - **Low**: `0 – 24`
   - **Moderate**: `25 – 49`
   - **High**: `50 – 74`
   - **Critical**: `75 – 100`
3. **AI Disaster Intelligence Agent**: Multi-provider cognitive agent backed by 8 typed, sandboxed tools subclassing `BaseTool`. Features untrusted input sanitization and strict **human authorization gates** before consequential operational actions can be executed.
4. **Disaster Scenario Simulation**: Multi-hazard stress-testing module (rainfall surge, multi-incident concurrency, team outages, shelter overflow, resource depletion) operating with **guaranteed state isolation** (zero live mutation).
5. **Intelligent Alerts & Notifications**: Automated rule-driven alerting with hash-based deduplication keys and a 15-minute cooldown window to prevent notification floods. Full lifecycle management (`active` -> `acknowledged` -> `resolved`).

## 3. Data Classification: Live, Cached, Simulated, Unavailable

AgentCraft maintains rigorous provenance tracking to prevent hallucinations or false claims:

| Status Label | Criteria | Visual Indicator in UI | Source Attribution |
|---|---|---|---|
| **Live** | Retrieved from external provider within the last 15 minutes, fresh and operational | Green pill (`LIVE`) | Provider name, coordinate query timestamp |
| **Cached** | Retrieved from in-memory cache within TTL (900 seconds) | Cyan pill (`CACHED`) | Provider name, cache retrieval age in seconds |
| **Simulated** | Generated by scenario engine or `TestDisasterDataProvider` for testing/training | Purple pill (`SIMULATED`) | Explicitly labeled as synthetic scenario |
| **Unavailable** | External provider connection failure, timeout, or missing coordinates | Amber pill (`UNAVAILABLE`) | Fallback heuristics, logged error, data gap penalty |

## 5. Feature 2: Explainable Disaster Risk Assessment Engine

- **Implementation**: [`backend/services/risk_engine.py`](file:///d:/AGENTCRAFT/backend/services/risk_engine.py)
- **Mathematical Formula**:
  $$\text{Score} = \min\left(100, \max\left(0, B_{\text{cat}} \times W_{\text{sev}} \times M_{\text{status}} + T_{\text{meteo}} + E_{\text{pop}} + U_{\text{uncertainty}}\right)\right)$$

### Factor Breakdown:
1. **Hazard Base Weight ($B_{\text{cat}}$)**:
   - Earthquake: 25.0
   - Landslide: 24.0
   - Flood: 22.0
   - Wildfire: 22.0
   - Severe Weather: 20.0
   - Industrial Accident: 20.0
   - Other: 10.0
2. **Reported Severity Weight ($W_{\text{sev}}$)**:
   - Critical: 30.0
   - High: 22.0
   - Medium: 12.0
   - Low: 5.0
3. **Operational Lifecycle Status ($M_{\text{status}}$)**:
   - Reported: +5.0
   - Under Assessment: +7.0
   - Confirmed: +8.0
   - Response Active: +10.0
   - Contained: -10.0
   - Resolved: -20.0
   - Closed: -25.0
4. **Hydro-Meteorological Telemetry ($T_{\text{meteo}}$)**:
   - Extreme precipitation ($\ge 50\text{ mm}$): +20.0
   - Heavy precipitation ($\ge 25\text{ mm}$): +12.0
   - Moderate precipitation ($\ge 10\text{ mm}$): +6.0
   - High river discharge: +15.0 (Moderate: +8.0)
   - High winds ($\ge 60\text{ km/h}$): +10.0
5. **Population Exposure ($E_{\text{pop}}$)**:
   - $>5000$ affected: +15.0
   - $>1000$ affected: +10.0
   - $>200$ affected: +5.0
6. **Data Gap Uncertainty Penalty ($U_{\text{uncertainty}}$)**:
   - Missing coordinates: +12.0 penalty, confidence drops -0.25
   - Missing weather data: +8.0 penalty, confidence drops -0.15

### Category Bands:
- **Low**: `0.0 – 24.9`
- **Moderate**: `25.0 – 49.9`
- **High**: `50.0 – 74.9`
- **Critical**: `75.0 – 100.0`

## 6. Feature 3: AI Disaster Response Agent & Tools

- **Tool Implementation**: [`ai/tools/disaster_tools.py`](file:///d:/AGENTCRAFT/ai/tools/disaster_tools.py)
- **Agent Service**: [`backend/services/disaster_agent_service.py`](file:///d:/AGENTCRAFT/backend/services/disaster_agent_service.py)

### The 8 Disaster Tools:
1. `get_incident_details(incident_id)`: Retrieves incident metadata, location, and population.
2. `get_incident_risk(incident_id)`: Calculates on-demand deterministic risk and factor breakdown.
3. `get_weather_observations(latitude, longitude)`: Obtains meteorological telemetry for coordinates.
4. `get_available_teams(status, specialization)`: Queries active response units ready for deployment.
5. `get_active_tasks(incident_id, status)`: Inspects ongoing operational missions.
6. `get_shelter_capacity(min_available_capacity)`: Evaluates evacuation centers and overflow conditions.
7. `get_resource_inventory(category, low_stock_only)`: Inspects emergency stockpiles.
8. `propose_response_plan(incident_id, team_ids, target_shelter_ids, priority_actions)`: Proposes tactical intervention. Marked with `requires_human_approval: True`.

### Safety & Human-in-the-Loop Safeguards:
- **Untrusted Input Sanitization**: Prompt injection strings (`ignore previous instructions`, `system prompt`, delimiter breakouts) are scrubbed from incident titles and descriptions.
- **Explicit Commander Confirmation**: AI proposed response plans create an uncommitted staging plan with `approval_status: pending_human_approval`. A human commander must issue an authorized sign-off (`/api/v1/intelligence/agent/plan/approve`) before tasks are created or team assignments finalized.

## 7. Feature 4: Disaster Scenario Simulations

- **Implementation**: [`backend/services/simulation_service.py`](file:///d:/AGENTCRAFT/backend/services/simulation_service.py)
- **Scenarios Supported**:
  1. `heavy_rainfall`: Simulates up to 100mm rain surge on existing floods and calculates risk delta.
  2. `multi_incident`: Injects concurrent simulated emergencies across sectors.
  3. `team_unavailability`: Models sudden loss of key responder units (NDRF/medical).
  4. `shelter_surge`: Injects evacuee spikes testing shelter saturation.
  5. `supply_shortage`: Simulates stockpile depletion for medical/ration items.
  6. `cascade_compound`: Compound multi-hazard catastrophe scenario.
- **State Isolation Guarantee**: Operates completely in memory using cloned entity models. Real incidents, teams, shelters, tasks, and alerts are strictly untouched.
- **Simulation Audit**: Records user parameters, baseline vs. simulated deltas, and timestamp in `disaster_simulations`.

## 8. Feature 5: Alert and Notification Engine

- **Implementation**: [`backend/services/alert_service.py`](file:///d:/AGENTCRAFT/backend/services/alert_service.py)
- **Threshold Triggers**:
  - `Critical Hazard`: Calculated incident risk $\ge 75.0$
  - `High Hazard`: Calculated incident risk between $50.0$ and $74.9$
  - `Severe Weather`: Precipitation $\ge 35\text{ mm}$
  - `Shelter Saturation`: Evacuee occupancy $\ge 85\%$
  - `Resource Depletion`: Stockpile quantity $\le 25\%$ of baseline
- **Deduplication Fingerprinting**: Computes SHA256 of `incident_id:rule_name:scope`. Active alerts with the same key within a **15-minute cooldown window** are suppressed.
- **Lifecycle Actions**: In-app actions allow operators to acknowledge (`acknowledged`) and resolve (`resolved`) alerts with user ID logging.
